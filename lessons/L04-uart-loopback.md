# L04 · UART：从"发一个字节"到"解析一条命令"

> 日期：2026-11-02 ｜ 60 分钟 ｜ 硬件：只需一根杜邦线（TX 与 RX 短接）

## ① 本节要学到什么

学完你能做这四件事：

1. **画出一帧 UART**：起始位 + 8 数据位 + 1 停止位 = 10 位，说清每个位的作用；
2. **手算 BRR**：知道 `BRR = f_CK / baud`，能算出 84 MHz / 115200 = 729，并算出实际误差；
3. **配置 USART**：时钟 → 引脚 AF7 → BRR → CR1（TE/RE/RXNEIE/UE）→ NVIC；
4. **分清中断与主循环的职责**：中断只把字节塞进环形缓冲，拼帧和解析全在主循环。

### 验收标准

| 步骤 | 预期现象 | 说明 |
| --- | --- | --- |
| 接短接线 | LED 每 2 秒亮灭切换 | 发送→回环→接收→解析→执行，全链路通 |
| 拔掉短接线，复位 | 5 秒后开始快闪（约 60 ms） | 收不到字节，程序自己报了"链路断" |

### 实验

**实验 A**：短接线在 / 不在，各看一次，确认代码能分辨"收到了"和"没收到"。

**实验 B**：把 `uart_puts(send_on ? "ON\r\n" : "OFF\r\n")` 改成 `"ONX\r\n"`，重新烧录。

- 现象：LED 不再亮（`strcmp` 匹配不上），但**仍然不报错**。
- 结论：解析是严格匹配的，多一个字符就整体失败——这就是为什么 NMEA 要校验和。

**实验 C（挑战）**：把 `uart1_init` 里的 `USART_CR1_RXNEIE` 去掉，改成主循环轮询：

```c
if (USART1->SR & USART_SR_RXNE) { rb_put((uint8_t)(USART1->DR & 0xFF)); }
```

比较两种写法：哪种更不容易丢字节？为什么？

## ④ 自测三题

1. 115200 8N1，一秒最多传多少个**字节**？一帧占几位？
2. `BRR = 729` 时，实际波特率是多少？误差百分之几？
3. 为什么中断里只做 `rb_put`，不直接 `strcmp` 判断命令？

<details><summary>参考答案</summary>

1. 10 位一帧（1 起始 + 8 数据 + 1 停止），115200 / 10 = **11520 字节/秒**。
2. 84,000,000 / 729 = **115226.3 bps**，比 115200 高 0.023%，远小于 UART 允许的 ±2%~3%。
3. 中断要尽快返回。`strcmp` 要等一整行、耗时可长可短，还可能被更高优先级中断打断；中断里做长逻辑会丢后续字节。环形缓冲把"快"和"慢"解耦。

</details>
