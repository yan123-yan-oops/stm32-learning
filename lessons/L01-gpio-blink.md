## ③ 动手

### 第一步：跑通原始代码

打开 `00-pio-blink` → Upload → 灯闪。

### 第二步：改延时，量周期

把 `delay_loops(20000000u)` 分别改成 `5000000u` 和 `50000000u`，各烧一次，用手机秒表数 10 个周期。

- 如果周期和延时值**成比例**，说明主频稳定；
- 如果比例不对，说明主频和你以为的不一样（这正是 L02 的伏笔）。

### 第三步：改闪烁节奏

改成「亮 200 ms、灭 800 ms」的不对称节奏（只改两个延时值），观察。

## ④ 自测三题

1. 不写 `RCC->AHB1ENR` 会怎样？为什么寄存器写进去像"没生效"？
2. `BSRR` 的高低 16 位分别做什么？为什么它比 `ODR ^= (1<<n)` 安全？
3. 这颗灯为什么写 0 是亮、写 1 是灭？

<details><summary>参考答案</summary>

1. 外设没有时钟就不响应写操作，读回仍是复位值。
2. 低 16 位置位（输出高），高 16 位复位（输出低）；单次写是原子操作，`ODR` 读-改-写会被中断打断丢状态。
3. 共阳接法：LED 阳极接 3V3，阴极接 PC13，低电平形成回路。

</details>

## 一个容易被忽略的细节

`GPIOC->MODER` 每个引脚占 **2 bit**，所以 PC13 对应 `13*2 = 26` 位：

```c
GPIOC->MODER &= ~(3u << 26);   // 先清两位
GPIOC->MODER |=  (1u << 26);   // 再写 01 = 通用输出
```

漏掉"先清后写"，就会把相邻引脚的模式一起改掉——这是新手最常见的坑。
